# Agent instructions

**THIS IS A PUBLICATION REPOSITORY, NOT A DEVELOPMENT REPOSITORY.**

Read this file and GOVERNANCE.md before making changes. Agents work here as
curators, validators, importers, documentarians, and release preparers.

- Develop applications, games, experiments, and tools in their separate,
  explicitly authorized development repositories. Never develop features in
  published source copies. If asked to do so, stop and report: "This belongs in
  the project's development repository."
- Work locally, collect a small coherent change, validate it, and show the human.
  No autonomous pushes or edit/commit/push loops. Prefer one meaningful commit
  per approved publication; never commit merely to demonstrate activity.
- No mass file generation, recursive documentation improvement, project tree
  dumps, or automatic synchronization. Import only explicitly allowlisted paths
  after preparing the manifest required by GOVERNANCE.md.
- Before modifying more than 10 files or creating more than 5 new files, stop
  and explain why; exceeding either limit requires explicit approval for the
  operation. Deleting, moving, or renaming published paths requires approval.
- Review secrets, personal data, licenses, assets, binaries, and generated files.
  Suspicious data blocks publication: report the path, reason, and remediation
  without exposing the value. Do not sanitize and publish automatically.
- Christopher Spitzner is the publication authority. Require explicit approval
  of the current, exact publication report. Broad instructions and approval from
  another task are insufficient. Any candidate change invalidates approval.
- Without that authorization, do not push, merge, publish, upload snapshots,
  create remote branches, tags, releases, issues, or pull requests; close issues;
  change settings, visibility, or licenses; enable Pages; create Actions; delete
  remote content; rewrite history; or force push.
- Initially no Actions, bots, Dependabot, scheduled jobs, auto-merge, release or
  documentation automation, synchronization, or autonomous agent triggers.
- Before a push, produce every publication-report field in GOVERNANCE.md and
  end with `PUBLICATION STATUS: AWAITING HUMAN APPROVAL`. Stop without pushing.
- After an approved publication, report repository, branch, commit SHA, changed
  files, publication/project ID, and remote URL. Then stop. Report later problems
  before attempting cleanup; do not start another commit or project.

The registry is canonical for project identity and status. Never invent facts,
metrics, dates, or license rights. Use "Not recorded." for missing historical
information and "Estimate." for estimates.
